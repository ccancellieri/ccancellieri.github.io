From the operating system to the platform

My engineering roots are in Linux, native programming and distributed data. A computer science thesis on grid environments led to the C++ SQL Handler for OPeNDAP Hyrax and Google Summer of Code. At GeoSolutions, I contributed to GeoServer and learned to build within an open-source community.

Today, at FAO, my work spans platform architecture, implementation and operations: GeoID and DynaStore, data discovery, identity, cloud infrastructure and the workflows that connect them. The work happens with engineers and colleagues across teams and disciplines.

I move between Linux, macOS and Windows, and between languages as the problem requires. Architecture matters to me when it helps a team make decisions, operate a system and change it with confidence.

Hyrax SQL Handler

Original Author GSoC 2009–2010

A C++ BES module enabling relational database access through the OPeNDAP Hyrax data server. Exposes databases accessed through ODBC (PostgreSQL, MySQL, SQLite, MongoDB) as standard OPeNDAP datasets.

GitHub

Remote Sensing Portal

Technical Lead & Architect 2022–Present

FAO's STAC-native earth observation discovery and access platform. Built on STAC-FastAPI with Elasticsearch / OpenSearch, exposing OGC STAC APIs across agricultural indicators, dekadal time series, and administrative boundary hierarchies.

Python FastAPI STAC OpenSearch Elasticsearch OGC API GCP Datacube
Portal GitHub
Engineering details and evidence Platform Highlights:
  • STAC-first architecture: OGC STAC standard end-to-end, from collection metadata through catalog search to item retrieval
  • Datacube workloads: Handles very large dimension spaces — thousands of agricultural indicators, dekadal time series (36 periods/year), administrative hierarchies
  • JSON-safe serialisation: Custom OpenSearch serialiser keeping STAC pydantic models (HttpUrl, datetime, UUID, Decimal) deterministic on ingest
  • Datetime range indexing: STAC `[[start, end]]` intervals mapped to Elasticsearch date_range objects with null-handling
  • Separate from the main catalog: Distinct runtime and data plane from DynaStore's core catalog, co-deployed on the same Keystone IAM and GCP substrate

The portal is the Organization's entry point for EO-aligned data discovery — complementing DynaStore's generic geospatial catalog with STAC-native search, item retrieval, and OpenSearch-backed faceting.

Public evidence with explicit boundaries:
  • Source and operation: v0.5.0-rc.1 Community source is public under AGPL-3.0-only for self-hosted evaluation. There is no Tellurion Cloud and no service-level agreement
  • Try a public file: COG and GeoParquet use bounded HTTPS range reads; ZIP Shapefile uses bounded temporary storage. Use a direct public HTTPS URL without credentials, query parameters, fragments or redirects. Sessions last up to 15 minutes and create no persistent tenant or catalog
  • Deployment: free Render services can sleep after inactivity. Hosted timings are not benchmark evidence
  • Release: the public evaluator and vector/STAC paths run public release-candidate source; historical raster, Zarr and 3D demos retain checksum-pinned 0.3 artifacts and their original terms
  • Reproducibility: version entry points retain dated viewer snapshots and checksums. Demo source and evidence now live alongside the engine; existing gallery links remain available. Retained pages do not guarantee historical service uptime
  • Rome measurement: the published result remains a Tellurion 0.2.0 smoke-scale benchmark with its method and caveats
  • Standards precision: demonstrated behavior is not presented as certification or blanket conformance

MCP Skill Hub

By Carlo Cancellieri Alpha (2026)

A Python MCP context service that brings relevant skills and task evidence into coding sessions. It keeps the original request intact, scopes retrieval to the project, and shows where each result came from.

Python FastMCP SQLite MCP
GitHub Design & boundaries Measured results Apache 2.0 license
Engineering details and evidence Engineering scope:
  • Scoped retrieval: Select task memory and skill descriptions for the current project, with size limits and source references
  • Reviewable context: Inspect the original prompt, supplemental evidence, sources and omissions in the Context page
  • Client integration: Use the same retrieval service through MCP or a prompt hook; leave permission and continuation decisions with the coding client
  • Smaller tool surface: An optional 8-tool profile measured 1,242 o200k_base tokens for serialized MCP schemas and instructions, down from 16,362 for the 87-tool profile (92.41% lower). This is a schema comparison, not a measure of total task usage
  • Resilient path: Pass the original prompt through when context is unavailable or retrieval times out

Interactive retrieval needs no local model or API key. Optional indexing and memory curation run outside the prompt path.

How I approach engineering

Make systems operable

A platform includes its deployment, diagnostics and recovery paths. FAO cloud operations and SWS delivery practices connect architecture to the work of running it.

Design for interoperability

The OPeNDAP database bridge and GeoServer work start from an interface people can use. Standards are useful when implementations make data accessible across tools.

Choose technology from constraints

Native code, grid computing, Python services and cloud infrastructure solve different problems. I choose around resource limits, integration needs and maintainability.

Lead through technical clarity

Reviewable decisions and shared understanding support delivery. Coordinating, reviewing and mentoring are part of the engineering work.
